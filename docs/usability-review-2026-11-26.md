# Moon desktop usability review

Renaming an occupied workspace was the most serious problem in the 26 November 2026 review. Reusing compiled window rules was the largest measured performance opportunity. The review covers Windows 11 release `2026.11.22-0`, commit `f3873de`. [Reviewed release](https://github.com/hongymagic/moon/releases/tag/2026.11.22-0)

## Usability findings

### High priority

- **Workspace renaming.** With two windows on workspace 2, I renamed it Research in a Settings fixture. The edit passed real Settings validation. Applying it in the layout engine sent both windows to workspace 1 and made it active. Alt+2 and Alt+Shift+2 then returned `unknown workspace "2"`. Give each workspace a stable identity so a rename preserves its windows, split proportions, focus and shortcuts. Show any affected personal rule before saving. [Name editor](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/settings/src/app.ts#L3741) · [Layout reload](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon-core/src/world.rs#L893)
- **Windows app switching.** Moon’s default hook consumes Alt+Tab for the recent workspace. With two windows on a fresh workspace and no previous workspace, focus stayed on the same window. Alt+Shift+Tab moves a workspace right. Keep Windows app switching available on first install, offer the current Moon mapping as a preset and test upgrades with customised bindings. [Moon defaults](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon-core/src/default.toml#L60) · [Hook behaviour](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon-win/src/hooks.rs#L641) · [Windows app switching](https://support.microsoft.com/en-us/windows/experience/how-to-multitask-in-windows)

### Daily use

- **Choosing a search result.** Searching *Code* in standalone Overview returned two windows. Pressing Down twice left focus on *Project notes*, and Enter activated it. Escape from that result left the picker open. At 740 × 560, the first result button began at y=588, below the visible area. Clicking the visible preview sent no activation request. Put matching rows first while searching, keep keyboard selection in view and let the preview activate its window. [Overview controls](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/settings/src/app.ts#L1857) · [Preview tiles](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/settings/src/app.ts#L1765) · [Windows keyboard guidance](https://learn.microsoft.com/en-us/windows/apps/develop/input/keyboard-interactions)
- **Reopening Overview.** Launching the published x64 companion twice with the same configuration and Overview argument produced two visible finders. Windows UI Automation detected the search field after 513 ms and 204 ms in those two launches. Reopening the finder should focus its search field in the existing window. A separate Settings window can then keep its unsaved draft. [Companion launcher](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon/src/main.rs#L225)
- **Finding recovery.** *Find a setting* returned zero hits for *pause*. Searching *stop* offered Recovery and opened General, which explains the emergency chord. The clickable Pause Moon and Restore windows and stop controls are under About. Index the action labels and focus the matching control when the user selects a result. Retain the restore confirmation. [Search index](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/settings/src/app.ts#L4395) · [Recovery controls](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/settings/src/app.ts#L4312)
- **Touch targets.** With ten workspaces, populated widgets and a 1920-pixel-wide display at 150%, the bar gave each workspace 24–29.3 logical pixels of width and 28 of height. These rectangles also determine hit testing. Microsoft’s general touch target is about 40 × 40 pixels at its reference scale. Give active and occupied workspaces larger targets when space is tight, with a labelled overflow control for the rest. Validate selection on a touch laptop. [Bar geometry](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon-core/src/scene.rs#L454) · [Microsoft touch guidance](https://learn.microsoft.com/en-us/windows/apps/develop/input/guidelines-for-targeting)

Both download links resolved to the correct installers. The released site emphasises x64. A concurrent edit in the checkout gives x64 and Arm64 matching download buttons. Add **Settings → System → About → System type** beside those choices so users can identify their processor. [Released download controls](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/website/app/page.tsx#L109) · [Installation guide](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/docs/installation.md#guided-setup)

## Performance

Opening Overview asks the daemon to build a catalogue of managed windows. The daemon evaluates the configured rules for each window. Its matcher compiles each regular expression again when checking it. A native Windows x64 probe compared the current matching path with an isolated prototype that reused the compiled patterns. [Catalogue construction](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon-core/src/desktop.rs#L180) · [Rule matcher](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/crates/moon-core/src/config.rs#L195) · [Rust regex guidance](https://docs.rs/regex/latest/regex/#avoid-re-compiling-regexes-especially-in-a-loop)

| Managed windows | Current median | Reused patterns median | Current p95 | Reused patterns p95 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 3.118 ms | 0.040 ms | 3.297 ms | 0.043 ms |
| 50 | 17.868 ms | 0.113 ms | 19.363 ms | 0.121 ms |
| 100 | 31.815 ms | 0.195 ms | 32.776 ms | 0.206 ms |

The release-mode probe spread synthetic editor windows across ten workspaces. Each path had three warm-ups and 41 interleaved samples. Both produced byte-identical catalogues at every size. The fixture exercised windows that matched none of the default rules. An independent run of the unmodified core measured 17.798 ms at 50 windows. These timings cover in-memory catalogue construction. WebView startup, IPC and presentation add time to the full interaction. [Probe sources and recorded results](usability-review-2026-11-26-evidence.zip)

Compile matchers when a configuration is accepted and replace them on reload. Verify matching and exclusion rules against the same window metadata. Measure the effect on opening Overview and on a shortcut arriving while the daemon handles that request.

The separate 50-window reducer and layout benchmark took **25.203 µs** on x64 WSL, within Moon’s **100 µs** budget. The earlier eight-window Windows placement probe recorded **11.944 ms median** and **29.496 ms p99** against targets below **10 ms** and **30 ms**. Current-release input-to-placement timing on physical x64 and Arm64 remains open. [Performance budgets](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/.claude/plans/moon-v1.md#L42) · [Earlier Windows measurements](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/docs/validation-performance.md#provider-demand-selection-native-validation-and-matched-static-pair)

## Feature priorities

1. **Recall a workspace when docking.** Moon already saves monitor assignments and appearance in named setups. Add an opt-in capture of a workspace’s open windows and split proportions. On reconnect, preview which windows will move, flag missing matches, and offer Apply and Undo. Test with two windows from the same app and one missing monitor. A user should be able to recover the desk layout without reopening apps or duplicating windows. PowerToys Workspaces provides a comparison for capture and restore. [Moon saved setups](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/docs/desktop-library.md) · [PowerToys Workspaces](https://learn.microsoft.com/en-us/windows/powertoys/workspaces)
2. **Edit splits directly in Overview.** Moon already supports moving a window to another workspace. Let a user drop it on the edge of a particular tile to split that tile, preview the result on the destination monitor, and undo the move. Give keyboard users the same destination and split choices. FancyZones demonstrates the pointer interaction of highlighting a destination during a drag. [FancyZones](https://learn.microsoft.com/en-us/windows/powertoys/fancyzones)
3. **Explain why a window did not tile.** Options already explains matching rules for a managed window. Add a user-invoked check for a missing window that can distinguish an ignore rule, a minimised window and an inaccessible app. Where a rule change can help, show its effect before saving. Test whether someone can diagnose an excluded window without opening TOML. [Window options](https://github.com/hongymagic/moon/blob/f3873de3ece1cd423ceaad7b94f994d1b3975ca1/apps/settings/src/app.ts#L1912)

## Verification

| Scope | Evidence |
| --- | --- |
| Local suites | 159 portable Rust tests, 82 Chromium Settings tests and 7 download tests passed. The targeted browser walkthrough used fixture windows and the built Settings frontend. |
| Published Windows x64 Settings | Six native WebView2 checks passed against a temporary configuration, covering load, draft Undo, save, concurrent edits, reload confirmation and Appearance controls. The two finder windows used for the launch check both closed. |
| Release CI | The native x64 and Arm64 jobs both passed. x64 checked foreground activation. Arm64 explicitly skipped native foreground, borderless fullscreen and external activation after the runner refused foreground access. Neither carousel job observed an active animation. [x64 job](https://github.com/hongymagic/moon/actions/runs/44977862550/job/137071667241) · [Arm64 job](https://github.com/hongymagic/moon/actions/runs/44977862550/job/137071667225) |

For release acceptance, run the same 128-shortcut, eight-window workload on physical x64 and Arm64 PCs. Record key-to-placement median and p99, hook p99, idle CPU and working set alongside the build, display scale, refresh rate and power mode. Exercise native Arm64 and emulated x64 apps together through focus, fullscreen and dock changes. A different installed daemon was managing the local x64 desktop during the review. [Windows on Arm](https://learn.microsoft.com/en-us/windows/arm/overview)

The usability evidence comes from task walkthroughs and automation. For a participant study, ask a new user to find their second editor window, rename its occupied workspace and pause tiling. Record wrong-window activations, lost workspace assignments and whether the user finds recovery unaided.
